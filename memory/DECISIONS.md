# Decisions

- Created a fresh scaffold because the chosen workspace was empty; no existing Terraform behavior or memory documents were present to preserve.
- Kept Jenkins outside this application state so the application pipeline cannot destroy the Jenkins server.
- Preserved the no-NAT constraint. A private subnet cannot install packages from public Ubuntu repositories; the DB therefore requires a compatible Ubuntu 24.04 amd64 AMI with AWS CLI/SSM Agent and either preinstalled MySQL or an offline package bundle delivered through the S3 gateway endpoint.
- DB password is generated by the database bootstrap only when no secret version exists and persisted in AWS Secrets Manager; Terraform manages secret metadata but not the password value.
- An AWS Secrets Manager endpoint and SSM endpoints are included because private instances need secret retrieval and SSM without a NAT route. The S3 gateway endpoint carries database package artifacts.
- The application EC2 instance is public only for Nginx HTTP:80; Node remains bound to loopback:3000. SSH is disabled unless a trusted CIDR is provided.
- The S3 artifact bucket is private, encrypted, versioned, and protected from accidental Terraform deletion. Application releases use unique build/commit keys.
- HTTP is the initial protocol. HTTPS is deferred until domain and certificate settings are supplied.
- Login uses bcrypt password hashes and random opaque session cookies; only SHA-256 hashes of session tokens are stored in MySQL. Sessions expire after eight hours and are revocable on logout. Cookies are HttpOnly and SameSite=Lax; Secure is enabled in production.
- The database bootstrap creates `auth_sessions` additively and grants the app user SELECT/INSERT/DELETE only on that table, plus SELECT/INSERT on `users`. It revokes stale database-level grants on that dedicated application user before reapplying least-privilege table grants.
- Local DB settings stay in ignored `app/.env`; no credential values are persisted in project documentation or memory.
